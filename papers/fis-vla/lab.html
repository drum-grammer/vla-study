보는 것

  1. 언어 5 · 이미지 패치 9 · 로봇 상태 1 · 노이즈 행동 1 토큰이 전부 (토큰 수, 16) 행렬. 세로로 이으면 (14, 16) 하나. 논문 그림 2 범례.

  4. 같은 중간 표현을 4번 재사용하며 상태 토큰만 바꿔 System 1을 돌린다 = 1:4 비동기.

  고주파 토큰 11개를 뒤에 붙임  : (14, 16) + (11, 16) → (25, 16)

가이드 1.8 · 2.6 · lab3_diffusion_action.py · 6초 · out/lab3_diffusion.svg

보는 것

  • 시연 데이터: 장애물을 왼쪽(x=−0.65) 또는 오른쪽(+0.65)으로 돌아가는 두 갈래. 조건 c로 위/아래가 바뀐다.
  • 행동을 직접 MSE로 맞히는 회귀는 (+0.00, +0.55) — 두 갈래의 가운데, 장애물 위. 실제 로봇이면 충돌.

모형: 공유 몸통(블록 31·32 역할) + 머리 A(4클래스 분류 = 이산 행동 토큰, 교차엔트로피 = Lslow) + 머리 B(노이즈 예측, MSE = Lfast). 1단계: A로 사전학습. 2단계: B를 배우되 A 손실을 빼거나 함께 둔다.

3. GPU가 있다면

스터디 범위 밖, 참고. 저장소 README(확인 2026-09-11) 기준으로 디스크 2GB 이상, CUDA 12 GPU(7B 추론에 24GB급), Ubuntu 전제.

  1. git clone https://github.com/CHEN-H01/Fast-in-Slow (LIFT3D 포함 약 700MB)
  2. conda Python 3.10, pip install -r requirement.txt, 추가로 dlimp_openvla · openvla · pytorch3d · flash-attn 2.5.5
  3. CoppeliaSim 4.1 설치, LIFT3D/third_party/RLBench와 LIFT3D를 pip install -e .
  4. HuggingFace haosad/fisvla 체크포인트
  5. test_rlbench.sh 경로를 고쳐 실행 — 기본 close_box, --slow-fast-ratio 4 --llm_middle_layer 30 --ddim-steps 4 --action-chunk 1, 20 에피소드

train.sh는 A800 8장 기준(배치 6/GPU, 300 에폭)이라 개인 GPU 학습은 현실적이지 않다. 스터디에서는 실습 6으로 코드를 읽는 것까지가 목표다.

4. 알려진 한계

  • 실습 4는 "순차 실행 비용"과 "이해가 낡는 비용" 두 힘만 뽑은 장난감이다. 최적 비율은 상수에 달려 있고, 논문의 1:4가 보편 상수라는 뜻이 아니다.
  • 실습 5의 "추론 능력"은 4클래스 분류로 대신했다. 논문의 Lslow는 LLM의 다음 토큰 예측이다.
  • 실습 2의 시간은 numpy 단일 스레드 값이라 GPU 트랜스포머의 절대 속도와 무관하다. 비율만 본다.
  • 저장소 줄 번호는 2026-09-11 main 기준. 실습 6은 앵커로 찾으므로 바뀌어도 동작하지만, 앵커 문자열 자체가 바뀌면 "찾지 못함"을 출력한다.
