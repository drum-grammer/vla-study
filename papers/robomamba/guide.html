1.1신경망 30초 복습

신경망은 입력을 출력으로 바꾸는 함수 f(x; θ)다. θ는 수백만~수십억 개의 숫자(파라미터)이고, "학습"은 정답과 출력의 차이(손실 함수)를 줄이는 방향으로 θ를 조금씩 고치는 일이다. 이 문서에 나오는 손실 함수는 세 종류다.

  • 교차엔트로피 — 분류·다음 토큰 예측. "정답 항목에 얼마나 높은 확률을 줬나"를 벌점으로 바꾼다. RoboMamba의 Stage 1이 쓴다.
  • L1(평균절대오차) — 연속값 예측. 차이의 절댓값 평균. 논문 식 (5), 접촉점 예측.
  • 측지 거리 — 두 회전 사이의 각도. 논문 식 (6), 그리퍼 방향 예측.

"2.7B 모델"은 θ가 27억 개라는 뜻이다. RoboMamba는 Mamba LLM 2.7B급(체크포인트 이름은 mamba-2.8b)에 CLIP 비전 인코더를 붙여 전체 약 3.1B다. 논문 4절은 "only 3.2B parameters"라 쓴다. 같은 모델을 세 가지로 세니, 인용할 때 무엇을 센 숫자인지 밝혀야 한다.

1.2토큰과 임베딩 — 모든 입력을 같은 크기의 벡터 열로

언어 모델은 입력을 토큰의 열로 받는다. 토큰 하나는 고정 길이의 실수 벡터(RoboMamba는 2560차원)다.

  • 텍스트 — 문장을 단어 조각으로 쪼개고 각 조각을 벡터로. "Predict the contact point" → 5~6개 토큰.
  • 이미지 — 224×224를 14×14 픽셀 격자로 나누면 16×16 = 256개 패치. 각 패치를 비전 인코더가 1024차원 벡터로 바꾼다.
  • 차원 맞추기 — 이미지 토큰은 1024차원, 언어 모델은 2560차원을 받는다. 그래서 작은 신경망(projector)으로 옮긴다.
💡 핵심 종류가 다른 정보라도 같은 차원의 벡터 열로 바꾸면 한 모델에 나란히 넣을 수 있다. 논문 그림 2에서 CLIP-ViT → Project Layer → Mamba로 가는 화살표가 정확히 이것이다.
실습 4실제 차원으로 토큰 열을 조립하고 projector 파라미터(21,242,880개)를 세어 본다.

1.3트랜스포머와 어텐션 — 그리고 왜 느린가

RoboMamba는 트랜스포머를 안 쓰는 논문이지만, 무엇을 대신하려는지 알아야 동기가 보인다.

비유 도서관에서 질문(Query)을 들고 서가를 돈다. 각 책에는 제목표(Key)가 붙어 있고, 질문과 제목표가 비슷할수록 그 책의 내용(Value)을 많이 가져온다. 모든 책의 내용을 "비슷한 정도"로 가중평균한 것이 답이다.

토큰 하나하나가 이 질문자다. 토큰들이 서로의 정보를 섞는 것이 어텐션이고, 뒤에 작은 MLP가 붙어 블록 하나가 된다. 이것을 여러 개 쌓은 것이 트랜스포머다(LLaMA2-7B는 32개).

문제는 비용이다. 토큰 L개가 서로를 다 보면 L×L개의 유사도를 계산해야 한다. 토큰이 두 배면 계산은 네 배다(O(L²)). 게다가 문장을 생성할 때는 새 토큰 하나가 이전 모든 토큰을 다시 읽어야 하므로, 들고 있어야 하는 메모리(KV 캐시)도 토큰 수에 비례해 늘어난다.

로봇에서 이게 왜 아픈가. 이미지 한 장이 이미 토큰 256개다. 손목 카메라를 더하고 과거 프레임을 쌓으면 L은 금방 1000을 넘는다. 논문 1절이 "expensive attention-based LLMs"라 적은 것이 이 얘기다.

실습 2어텐션과 SSM의 계산 시간을 L=64~2048에서 직접 재고 증가율을 비교한다. 어텐션 ×76.0, SSM ×23.2.

1.4순환신경망과 상태 — SSM의 조상

어텐션 말고 다른 방법이 있다. 과거를 요약한 메모(상태)를 들고 다니는 것이다.

for t in 토큰들:
    상태 = f(상태, 토큰[t])      # 메모를 갱신
    출력[t] = g(상태)             # 메모를 보고 답한다

토큰 하나 처리 비용이 항상 같으므로 전체가 O(L)이고, 들고 있는 메모 크기는 L과 무관하게 고정이다. 대가는 "메모에 다 못 담는다"는 것.

상태공간모델(SSM)은 이 f를 아주 단순한 선형식으로 제한한 것이다. 제어공학에서 온 형태이고, 논문 식 (1)이 그 연속시간 버전이다.

논문 식 (1) · 연속시간 
h′(t) = A h(t) + B x(t)
y(t)  = C h(t)

A ∈ R^(N×N)   상태가 스스로 어떻게 변하나
B ∈ R^(N×1)   입력을 상태에 얼마나 넣나
C ∈ R^(N×1)   상태에서 출력을 어떻게 뽑나

토큰은 띄엄띄엄 오니까 이 미분방정식을 "Δ만큼의 시간 동안 입력이 일정했다"고 보고 적분해 둔다(이산화, zero-order hold).

논문 식 (2)(3)(4) · 이산화와 순환 
Ā = exp(ΔA)                             ... 식 (2)
B̄ = (ΔA)⁻¹ (exp(ΔA) − I) · ΔB          ... 식 (3)

h_t = Ā h_(t−1) + B̄ x_t                ... 식 (4)
y_t = C h_t

식 (4)는 그냥 for 문이다. 여기서 Δ가 이 논문 전체의 주인공이다.

ΔĀ = exp(ΔA)뜻
작다 (0.001)0.9990과거를 거의 그대로 보존, 지금 입력은 거의 무시
중간 (0.1)0.9048—
크다 (5.0)0.0067과거를 지우고 지금 입력을 크게 받아들임
 A가 음수로 학습되므로 Ā = exp(ΔA)는 항상 0~1 사이다. A = −1로 놓고 계산한 값.
실습 1식 (1)~(4)를 숫자로 확인하고, Δ만 바꿨을 때 정보가 몇 토큰까지 살아남는지 측정한다. Δ=0.02면 55토큰, Δ=2.0이면 2토큰.

1.5Mamba — 선택적 상태공간모델(S6)

S4 같은 이전 SSM은 A, B, C, Δ가 학습된 상수였다. 한 번 정해지면 모든 토큰에 같은 규칙을 적용한다. 그래서 "이 토큰은 중요하니 기억하고, 저 토큰은 넘기자"를 할 수 없다.

Mamba(2023)의 기여는 한 문장이다 B, C, Δ를 입력의 함수로 만들었다. 논문 3.1절 마지막 문단이 이것을 설명한다. B, C ∈ R^(batch×L×N)로 토큰마다 다르고, Δ ∈ R^(batch×L×D)로 토큰마다·채널마다 다르다. 이 구조를 선택적 스캔(selective scan, S6)이라 부르고, 논문이 말하는 "content-aware reasoning"이 이것이다.

저장소에서는 세 줄이다. 입력 x에서 x_proj로 Δ·B·C의 재료를 뽑고, dt_proj + softplus로 Δ를 만든다. Mamba 블록 하나의 전체 흐름:

x (2560차원)
 ├─ in_proj ──→ 두 갈래로 5120차원씩 (본 경로 x, 게이트 z)
 │   x ─→ 인과 1D 합성곱(커널 4) ─→ SiLU      # 직전 3토큰의 국소 문맥
 │     ─→ x_proj ─→ [Δ재료 160 | B 16 | C 16]
 │     ─→ dt_proj + softplus ─→ Δ (5120차원)
 │     ─→ 선택적 스캔 (식 2·3·4) ─→ y
 │   y = (y + x·D) × SiLU(z)                  # 잔차 + 게이트
 └─ out_proj ──→ 2560차원

이 블록을 64개 쌓은 것이 mamba-2.8b다. 트랜스포머의 32블록과 비교하면 블록 수는 두 배지만, 블록 하나가 더 싸다.

1.6MLLM — 이미지를 LLM에 넣기

MLLM(다중모달 대규모 언어모델)은 LLM 앞에 비전 인코더를 붙여 이미지도 토큰으로 넣을 수 있게 한 것이다. LLaVA 계열의 조합법이 표준이 됐다.

  1. 비전 인코더 — 이미지 → 패치 토큰. RoboMamba는 CLIP ViT-L/14를 쓴다.
  2. 연결기(projector) — 비전 토큰의 차원을 LLM 차원에 맞추는 작은 MLP.
  3. LLM — 언어 토큰과 이미지 토큰을 한 줄로 받아 처리.
RoboMamba가 일부러 안 한 선택 (3.2절) 여러 비전 인코더를 동시에 쓰는 앙상블(DINOv2 + CLIP-ConvNeXt + CLIP-ViT)을 쓰지 않았다. Cobra·SPHINX가 쓰는 기법인데, 논문은 "추가 계산 비용이 실세계 실용성을 심하게 해친다"며 CLIP 하나만 쓴다.

참고로 FiS-VLA는 SigLIP + DINOv2 두 개를 쓴다 — 같은 회사가 공저자인 두 논문이 반대 선택을 했다.

명령어 튜닝은 "이미지 + 질문 → 답" 형태의 데이터로 추가 학습해 지시를 따르게 만드는 것이다. RoboMamba의 Stage 1.2가 이것이다.

1.7로봇 조작 문제를 학습 문제로 바꾸기

입력(관측): RGB 이미지 한 장 + 언어 질문. 끝이다. RoboMamba는 포인트클라우드도, 로봇 상태(관절 각도)도, 과거 프레임도 안 받는다. FiS-VLA와 가장 크게 다른 점이다.

출력(행동): SE(3) 포즈 — 3차원 위치 + 3차원 회전. 그리퍼의 "어디를, 어떤 자세로 건드릴지"다. 논문은 Franka Emika Panda 팔의 6-DoF로 표현한다.

  • 위치 a_pos — 단, 시뮬 실험에서는 이미지 위의 2D 접촉점 (x, y)만 예측하고 깊이 카메라 정보로 3D로 되돌린다(3.4절). 저장소 첫 헤드의 출력이 2개인 이유다.
  • 방향 a_dir — 회전행렬. 실제 코드는 6개 숫자를 내놓고 Gram-Schmidt로 3×3을 만든다.
  • 잡기 과제면 그리퍼 개폐를 더해 7-DoF.
⚠️ 왜 9개가 아니라 6개인가 — 논문에 없고 코드에만 있는 사실 신경망이 9개 숫자를 그냥 뱉으면 그것이 회전행렬일 보장이 없다(RᵀR = I 도, det = +1도 깨진다). 6개를 두 벡터로 보고 Gram-Schmidt를 돌리면 항상 유효한 회전이 나온다. 논문 3.4절은 a_dir ∈ R^(3×3)이라고만 쓴다 (저장소 manip.py bgs(), 확인 2026-09-11).

학습 방식: 시뮬레이터에서 "성공한 시도"만 모아 지도학습한다. 사람 시연(모방학습)이 아니라 규칙 기반 자동 수집이다(4.1절). 무작위로 가동부의 접촉점을 고르고, 그리퍼 z축을 표면 법선 반대로 두고, y축은 임의로 정해 찔러 본다. 물체 관절이 움직였으면 성공 샘플로 저장한다.

실습 5이 수집 규칙의 "y축은 임의" 한 줄이 식 (6) 손실에 무엇을 하는지 직접 확인한다. 회전 전체 오차가 93.7°에서 바닥을 치는데도 성공률은 95.5%다.

1.8개루프 vs 폐루프, 그리고 관절 물체

개루프는 한 번 판단해서 한 번 움직이고 끝. 폐루프는 행동 → 새 관측 → 다음 행동을 계속 반복한다.

RoboMamba의 시뮬 평가는 개루프다(4.1절). 접촉점과 회전을 한 번 예측해 찔러 보고, 물체 관절 상태가 0.1 m 넘게 변했으면 성공이다. 이것이 표 2의 성공률이다.

⚠️ 9.0 Hz를 폐루프 제어 주기로 읽으면 틀린다 논문에 폐루프 제어 실험은 없다. FiS-VLA의 21.9 Hz / 117.7 Hz와 직접 비교할 수 없는 숫자다(그쪽은 행동 청크·폐루프 기준).

관절 물체는 서랍·문·노트북 뚜껑처럼 경첩이나 레일로 연결된 가동부가 있는 물체다. 논문은 PartNet-Mobility의 30개 범주를 쓴다(학습 20 + 평가 전용 10). 과제는 주로 "당기기"다.

1.9VLA와 행동을 어떻게 내보내는가 문제

VLA = MLLM에 행동 출력을 붙인 것. 방식이 두 갈래다.

  1. 행동을 토큰으로 이산화 (RT-2, OpenVLA) — Δx를 256개 구간으로 쪼개 "구간 137번" 토큰을 만들고 텍스트 생성하듯 하나씩 뽑는다. LLM을 고칠 필요가 없지만 느리고 행동이 끊긴다.
  2. 별도 정책 헤드 — 연속값을 한 번에 내놓는 작은 신경망을 붙인다. RoboMamba가 이 방식이고, 헤드가 MLP 두 개뿐이다.

FiS-VLA·π0·CogACT는 2번의 정교한 버전(확산 모델 헤드)을 쓴다. RoboMamba의 헤드는 확산도 아니고 시퀀스도 아니라 그냥 MLP다 — 개루프 단발 포즈 예측이라 그걸로 충분했다.

Stage 1.2의 co-training이 이 논문의 핵심 주장이다. 일반 VQA만 쓰지 않고 로봇 데이터를 섞는다. 이유가 둘이다. ① 로봇 추론 능력을 얻는다 ② 일반 추론도 같이 좋아진다(로봇 데이터에 복잡한 추론이 섞여 있어서).

논문이 드는 구체적 예가 설득력 있다. 기존 MLLM은 "전자레인지를 열어라"에 "1단계: 손잡이를 찾아라"라고 정형적으로 답하는데, 손잡이 없는 전자레인지가 많다. 실제 장면을 보고 답해야 하므로 환각(POPE)을 줄이는 것이 로봇에서 중요하다.

논문 식 (5) · 위치 
L_pos = (1/N) Σ |a_pos − a_pos^gt|

접촉점의 L1 손실. 차이의 절댓값 평균.

논문 식 (6) · 방향 
L_dir = (1/N) Σ arccos( (Tr(a_dir^gt ᵀ · a_dir) − 1) / 2 )

말로 풀면 "예측한 회전과 정답 회전 사이의 각도(라디안)"다. 두 회전이 같으면 Tr(RᵀR) = 3이고 arccos(1) = 0. 완전히 반대면 π.

⚠️ 저장소의 clamp 저장소는 arccos의 인수를 clamp(−1+1e−6, 1−1e−6)로 자른다. 부작용으로 완벽히 맞혀도 손실이 0이 아니라 약 0.081°에서 바닥을 친다.
실습 5식 (5)(6)을 그대로 손실로 써서 헤드를 학습시킨다. 노트북 CPU로 10초, 접촉점 오차 0.031, z축 오차 3.2°, 성공률 98.7%. 논문의 "a few dozen minutes on a single A100"이 왜 가능한지 구조로 보인다.

향후 방향(5절): ① 더 발전된 선형 복잡도 LLM으로 프레임워크 이식, ② 4D 로봇 VLA — 3D 포인트클라우드와 시간 데이터를 더한다.

📌 ②가 그대로 FiS-VLA로 이어진다 FiS-VLA는 포인트클라우드 1024점과 로봇 상태를 System 1 입력으로 받는다. RoboMamba의 "향후 계획"이 다음 논문의 설계가 된 셈이다. 단, ①은 지켜지지 않았다 — 백본은 Mamba가 아니라 트랜스포머(LLaMA2)로 되돌아갔다.

2.10비판적으로 읽기 — 스터디에서 따져 볼 것

  1. 개루프와 폐루프의 혼동 위험. 9.0 Hz는 "한 번 추론에 111 ms"다. 논문에 폐루프 제어 실험은 없다. 그런데 그림 1은 이 값을 "Inference Speed"로, 1절은 "highest control frequency"로 부른다. control frequency라는 표현은 폐루프를 연상시키는데 실험은 개루프다.
  2. 속도 배수의 기준이 두 개(초록 3배 = OpenVLA 대비, 4.2절 7배 = ManipLLM 대비).
  3. 파라미터 수의 논문↔코드 불일치(3.7M vs 8.20M, 45.2M vs 90.69M).
  4. 부록 표 4의 인코더 라벨 상충.
  5. 식 (6)의 바닥이 막혀 있다. 4.1절 데이터 수집이 y축을 임의로 정하므로 정답 회전의 z축 주위 성분이 장면의 함수가 아니다. 흡착 그리퍼라 성공률에는 영향이 거의 없지만 식 (6)을 지표로 쓰면 모델 비교가 안 된다. 논문이 회전 오차를 표로 내지 않고 성공률만 보고하는 것과 맞아떨어진다. 논문 5절에 이 얘기는 없다.
  6. co-training의 효과 주장이 증거보다 강하다. GQA는 세 쌍 모두에서 내려간다.
  7. "이해 → 조작" 인과의 방향. 그림 3 b)는 상관을 보여 준다. 백본 네 개가 크기·구조·학습 데이터가 모두 달라 "추론 능력" 하나만 변한 실험이 아니다. 가장 통제된 비교는 Ours-2.7B vs Ours-2.7B(w/o C) 한 쌍뿐이다.
  8. 동결의 대가를 측정하지 않았다. "헤드만 vs 어댑터도 함께" 같은 대조 실험이 없다.
  9. 공개 범위. 학습 코드 비공개, 조작 평가 스크립트 없음, 체크포인트는 test 브랜치. 같은 회사가 공저자인 FiS-VLA는 학습·평가 모두 공개했다 — 왜 다른가가 협업 논의의 실질 질문이다.
  10. v2 기준으로 읽었다. v1(2024-06-06)에서 바뀐 내용은 확인하지 않았다(미확인).

  1. B·C·Δ를 학습된 상수가 아니라 입력의 함수로 만들어, 토큰마다 "기억할지 넘길지"를 정할 수 있게 했다(선택적 스캔, S6).
  2. Δ가 크면 Ā = exp(ΔA) ≈ 0 → 과거를 지우고 지금 입력을 크게 받는다. 작으면 Ā ≈ 1 → 과거를 보존하고 지금 입력을 거의 무시한다. (실습 1: Δ=0.02는 55토큰, Δ=2.0은 2토큰)
  3. RGB 이미지 한 장 + 언어 질문뿐이다. FiS-VLA는 추가로 3D 포인트클라우드와 로봇 상태를 받는다(이미지도 3장).
  4. 1.1: Project Layer만 학습, 비전 인코더·Mamba 동결. 1.2: Project Layer + Mamba 학습, 비전 인코더 동결. 2: 정책 헤드만 학습, 나머지 전부 동결.
  5. 식 (5) = 접촉점 위치의 L1 손실. 식 (6) = 그리퍼 방향의 측지 거리(두 회전 사이 각도) = arccos((Tr(R_gtᵀR_pred) − 1)/2).
  6. seen 0.63 / unseen 0.53. ManipLLM(0.56 / 0.51) 대비 +7%p / +2%p. 20개 중 14개 SOTA.
  7. 초록의 "3 times"는 OpenVLA 대비(3.4 → 9.0 Hz). 4.2절의 "7 times"는 LLaMA-AdapterV2 / ManipLLM 대비(1.1 → 9.0 Hz).
  8. unseen이 더 크게 떨어진다(0.53 → 0.41 vs seen 0.63 → 0.61). 로봇 데이터를 섞는 이득이 주로 일반화에 있다는 뜻이다.
  9. 63.7% → 63.2%로 거의 같다(부록 표 6). 병목이 헤드가 아니라 백본의 표현에 있다는 뜻이고, 그래서 "이해가 먼저"라는 주장을 받친다.
  10. 밝힌 것: 2.7B LLM이라 복잡한 추론에서 7B/13B 기반 MLLM에 뒤진다(5절). 밝히지 않은 것(예): 개루프인데 "control frequency"라 부른 것, 임의 y축 때문에 식 (6)의 바닥이 막힌 것, co-training이 GQA를 일관되게 떨어뜨린 것, 논문↔코드 파라미터 불일치, 동결의 대가를 재는 대조 실험 부재.
